API Versioning Strategies: 
Nishi detailed various API versioning strategies, including URI, header, query parameter, and media type versioning, discussing their benefits and drawbacks and emphasizing best practices such as limiting supported versions and signaling endpoint retirement.
	URI Versioning: Embedding the version number in the URL path (e.g., /api/v1/users) provides visibility and ease of testing but can clutter URLs and break REST resource uniqueness.
	Header and Query Parameter Versioning: Specifying the version in HTTP headers or as a query parameter keeps URLs clean and can make versioning optional, but may reduce transparency and is less standard in some cases.
	Media Type Versioning and Best Practices: Media type versioning allows clients to request specific data representations, supporting gradual migration. Nishi recommended supporting only a few versions and using HTTP sunset headers to signal deprecation.
