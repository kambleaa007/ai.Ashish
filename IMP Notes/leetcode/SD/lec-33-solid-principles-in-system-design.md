# Lecture 33: SOLID Principles in System Design [1]

## Overview
Applies object-oriented software design principles to low-level system design [1].

## The 5 Principles
1. **Single Responsibility Principle (SRP)**: A class/service should have one reason to change [1].
2. **Open/Closed Principle (OCP)**: Software entities should be open for extension, closed for modification [1].
3. **Liskov Substitution Principle (LSP)**: Derived classes must be substitutable for base classes [1].
4. **Interface Segregation Principle (ISP)**: Prefer small, client-specific interfaces over large general ones [1].
5. **Dependency Inversion Principle (DIP)**: Depend on abstractions, not concrete implementations [1].

## Summary & Key Takeaways
SOLID principles ensure clean, testable, and maintainable code bases in large-scale software engineering [1].
