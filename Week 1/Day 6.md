Think of the entire application as a secure building with multiple security checkpoints. The meeting repeatedly connected all topics using this model.

1. Identity → Authentication

Question: Who are you?

User registers and logs in.
Password is hashed and verified.
JWT access token is issued.
Refresh token is stored for obtaining new access tokens later.

Mental Model:
 👉 Authentication proves identity.

User → Login → Verify Password → Issue JWT

2. Permission → Authorisation (RBAC)

Question: What are you allowed to do?

The application separates users into roles such as:

User
Admin

The role is checked before accessing protected resources. Admins can perform broader operations than normal users. Much of the discussion focused on how to assign and manage these roles securely.

Mental Model:

Authenticated User
        ↓
    Check Role
        ↓
User → Own Resources
Admin → All Resources

3. Session Continuity → Access Token + Refresh Token

Question: How do users stay logged in securely?

Access tokens are short-lived.
Refresh tokens are longer-lived.
When the access token expires, the refresh token is used to obtain a new one.
Users do not need to log in repeatedly.

Mental Model:

Login
  ↓
Access Token (Short Life)
  ↓ Expired
Refresh Token
  ↓
New Access Token
