Important Rules Discussed
Never Change Field Numbers

Field numbers act as identifiers in protobuf messages.

Changing them can break message compatibility.

Backward Compatibility

Newer code should be able to read older data formats.

Forward Compatibility

Older services should safely ignore unknown fields.

Reserved Keywords

Removed fields should be marked as reserved to avoid accidental reuse.

Optional Fields

Proto3 optional fields allow systems to distinguish:

Default values
Intentionally supplied values
